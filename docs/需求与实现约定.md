# 租赁管理展示项目：需求与实现约定

目标岗位：Java 后端开发。项目定位：在原学习 Demo 基础上、借助 AI 协作完善的个人学习与演示项目，全部样例数据为虚构数据。

## 演示范围

房源维护 → 租客登记 → 签约占用房源 → 按月生成账单 → 分次收款 → 结清当前欠款后退租释放房源。另提供经营概览、用户与角色管理、操作日志、接口说明和自动化验证。

## 本轮采用的业务约定

以下为这个展示版本的明确设计，后续可按实际业务调整，不代表来自某家企业的真实需求。

- 房源具有空置、已出租、下架三种状态；同一房源最多一份生效合同。签约立即占用房源，不支持未来档期预约。
- 合同以整月为周期，租期 1—24 个月；租金在签约时形成快照。结束日期由起租日与租期推导。当前版本不做按日折算。
- 签约一次生成各月租金账单，月账单唯一；租金为人民币元，使用 BigDecimal 和 DECIMAL(12,2)。押金作为合同约定记录，暂不提供自动退押或第三方资金结算。
- 收款可以分次，累计金额不得超过账单金额；调用方提供幂等号，相同幂等号及相同请求重复提交只记一笔，变更请求内容则拒绝。
- 退租要求已到期账单全部结清；未来未收款账单取消。未来账单已有收款时拒绝直接退租，避免隐含退款。退租和释放房源在同一事务中完成。
- 房源、租客使用逻辑删除。有生效合同时不能删除关联房源或租客。
- 管理员具有系统维护和全部业务权限；运营可以维护租赁资料、签约和收款；观察员仅可读取。服务端执行鉴权，页面隐藏按钮只是交互辅助。
- 会话空闲 30 分钟过期；同一账号只保留最近一次登录。禁用用户或调整角色后撤销其现有会话。
- 同一账号连续登录失败 5 次后，在本次失败窗口内限制登录 5 分钟；成功登录清除失败计数。
- 出租率采用“已出租 / 未归档的在管房源”计算，分母包含已下架房源；月实收按本月实际登记的收款流水统计。
- 用户界面分页从 1 开始，页容量限定 1—100，搜索重置页码。查询值使用参数绑定。

## 验收重点

正常租赁闭环、非法参数、越权写入、已出租房源重复签约、并发签约、重复收款、超额收款、收款事务回滚、退租释放房源、禁用与权限调整后的会话撤销、接口不泄漏密码、全新数据库初始化与可复现构建。

未承诺上线商业环境、真实支付对接、大规模性能指标或真实用户数量。简历只描述实际完成并验证的能力。
