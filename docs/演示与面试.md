# 五分钟演示与面试准备

## 演示前

启动 Docker Desktop，运行启动demo.ps1 和初始化演示数据.ps1，打开 http://localhost/login 。管理员 admin / 111111。演示前先运行验证项目.ps1；若本次修改触发重编译，之后再次启动demo.ps1，确保展示服务已恢复。

样例数据为虚构数据。请不要修改原用户表中的个人记录来做展示；创建新演示账号即可。演示产生的数据会持久保存。

## 五分钟路线

1. **30 秒：经营概览**。说明在管房源、生效合同、本月实收、出租率和应收均来自数据库，不是静态数字。应收包含未到期账单。
2. **1 分钟：新增业务资料**。新增唯一编号的房源，例如 TALK-20261015；登记虚构租客，手机号避免与已有样例重复。
3. **1 分钟：签约与账单**。选择空置房源，今天起租 3 个月；展示合同租金快照、房源已出租和自动生成的三张月账单。解释同房源重复签约会被服务端拒绝。
4. **1 分钟：分次收款**。对第一张账单先收一部分，再结清；展示流水和 PARTIAL → PAID 状态。说明这是线下收款登记，不连接真实支付。
5. **30 秒：退租**。当前到期账单结清后退租，展示未来未收账单取消、房源恢复空置。若有未来预收则会拒绝，避免凭空退款。
6. **1 分钟：工程证据**。展示角色权限、审计请求编号与测试报告，解释 8 并发签约只有一个赢家，4 次同号收款只有一条流水。

在项目当前环境录制即可；不要为了录屏清空数据库。录屏中避免展示旧个人资料或任何令牌。

## 关键代码阅读顺序

- service/RentalRules.java：日期和金额规则，先理解纯函数与边界测试。
- service/RentalService.java：sign、pay、close；画出事务与加锁顺序。
- persistence/RentalMapper.java 与 db/V1__portfolio.sql：SQL 和数据库约束互相核对。
- auth/SessionService.java：登录替换、续期、退出、禁用撤销。
- auth/AuthInterceptor.java 与 api/*：服务端鉴权及请求绑定。
- common/Errors.java 与 config/TraceFilter.java：统一错误和定位方式。
- RentalApiIT.java：读真实 HTTP 断言，对照数据库最终状态。

以上后端路径相对于 system-admin/src/main/java/com/rental；测试位于 src/test/java/com/rental，SQL 位于 src/main/resources。

## 面试解释示例

**“你怎样保证一套房只出租一次？”**

同一事务先对房源加行锁，确认空置后生成合同、账单并改变状态；第二个事务等待锁后看到已经出租，返回冲突。另有基于 ACTIVE 合同生成列的唯一索引防止绕过服务层写出重复合同。测试是 8 个并发请求，断言 1 个成功、其他 409；这验证正确性，不代表系统容量。

**“重试为什么不会收两次？”**

调用方为同一笔业务保存幂等号，后端锁合同、锁账单后查询该号；相同内容返回已有流水，不同内容返回冲突。新号才检查余额并入账，流水和实收更新同一事务提交。唯一索引为并发兜底。HTTP requestId 每次请求都不同，不能代替业务幂等号。

**“有哪些不足？”**

这是单体演示。没有退款/退押、按日计租、真实支付与生产压测，框架版本保留了旧项目基线。Redis 会话撤销与数据库没有分布式事务。下一步优先补业务模型、基线升级和迁移工具，而不是空加中间件。
