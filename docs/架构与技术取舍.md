# 架构与技术取舍

## 从原 Demo 改造

原项目使用 Vue、Spring MVC、MyBatis 与 Tomcat，主要可用流程集中在登录和用户表。当前新增独立的 com.rental 代码包，旧包、旧 Mapper 和旧页面移入 legacy；Spring 扫描与路由只使用当前实现。Maven 从声明的依赖编译，脱离原 out/ 编译产物。

继续使用 Java 11 / SSM / WAR，是为了保留项目演进的可解释性。Spring Boot 改造、框架支持周期升级可作为后续学习项，本版不宣称已完成。

## 请求与事务分层

HTTP → TraceFilter（请求编号）→ AuthInterceptor（身份与权限）→ Controller（DTO 校验）→ Service（业务规则和事务）→ MyBatis → MySQL。

查询与写入 DTO 分开：客户端不能直接提交实收累计值、合同状态或 OCCUPIED 房源状态。统一响应带 requestId，日志使用 MDC，业务写入同时保存审计记录。错误响应不返回 SQL、堆栈或密码。

## 签约并发控制

事务先 SELECT FOR UPDATE 锁定房源，确认 VACANT，再锁定租客。随后插入合同、按起租日逐月生成账单、更新房源 OCCUPIED、写入审计，最后一起提交。其他签约请求等待同一房源锁，醒来后检查到已占用而返回 409。

数据库再提供兜底：合同生成列 active_house_id 仅在 ACTIVE 时等于 house_id，其他情况为 NULL；唯一索引限制同房源最多一份生效合同。MySQL 允许多条 NULL，因此历史结束合同可以并存。月账单另有 (contract_id, period) 唯一约束。

房源编辑还使用 version 条件更新，检测用户基于旧页面覆盖修改。version 不能代替签约事务的锁和唯一约束。

## 收款与幂等

~~~mermaid
sequenceDiagram
    participant C as 调用方
    participant S as 收款服务
    participant D as MySQL
    C->>S: billId + amount + requestId
    S->>D: 锁合同 → 锁账单
    S->>D: 查询 requestId
    alt 相同请求已入账
        S-->>C: 返回已有流水
    else 新请求
        S->>S: 检查未取消、金额不超余额
        S->>D: 插入流水 + 更新累计实收和状态 + 审计
        D-->>S: 同一事务提交
        S-->>C: 收款流水
    end
~~~

收款采用 READ_COMMITTED：前置查询只用于确定要锁的合同，等待锁后查询幂等记录时，需要看见前一个事务刚提交的流水。若沿用 REPEATABLE_READ 下较早建立的一致性快照，重复请求可能看不到新流水。

幂等号在数据库全局唯一。重复请求需同时核对账单、金额、收款方式和备注；同号不同请求返回 409。跨账单抢用同一幂等号由唯一索引兜底并回滚失败事务。当前接口登记的是线下收款事实，不调用银行或支付平台。

## 退租与锁顺序

退租：房源 → 合同 → 按 ID 排序的账单；收款：合同 → 账单。收款不反向申请房源锁，避免形成这两类操作间的锁环。

退租要求到期账单结清，未来存在实收时阻止退租，未来未收账单取消。合同结束、房源释放、账单取消、审计位于同一 MySQL 事务。数据库异常由事务回滚；当前自动化测试没有注入数据库中断，不能把正常与超额场景宣称为所有故障回滚验证。

## 身份、会话和密码

- 使用 JDK PBKDF2WithHmacSHA256、随机盐、600000 次迭代和常量时间结果比较；启动时将旧明文值迁移为散列。
- 认证专用 AuthRow 与安全 Principal / UserView 分离，响应不携带密码字段。
- 令牌使用 32 字节随机数；Redis 精确键定位，不执行 KEYS 全库扫描。
- rental:session:{token} 保存安全身份快照，rental:user-session:{id} 索引最近令牌。两个键均空闲 1800 秒过期。
- Lua 原子替换、续期与撤销；续期先核对用户索引，已替换令牌不能复活。
- 账号禁用、角色修改撤销现有会话；接口服务端按 admin / operator / viewer 策略鉴权。
- 每个受保护请求再次读取数据库账号状态与角色，拒绝并撤销已停用或角色变化的身份，覆盖“登录与禁用交错、撤销后才写入会话”的情况。这增加两次小查询，当前优先保证授权规则清晰，尚未压测这部分开销。
- 同账号失败计数使用原子 INCR + 首次 EXPIRE，避免永久锁定。

参数参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。本项目没有第三方安全审计。

数据库修改与 Redis 撤销没有分布式事务。当前采用“撤销失败则接口失败、数据库回滚”的保守处理；仍可能出现数据库后续失败但会话已经被撤销的情况，用户可重新登录。多实例中权限修改和进行中的请求也不保证瞬时全局撤回。若用于真实业务，需进一步设计事务后事件、重试与权限版本校验。

## 查询与运维

MyBatis 参数绑定；列表分页限制每页最多 100。账单到期状态、合同关联、收款时间有索引，未进行大数据量执行计划或性能压测，因此不写“查询提升 X%”。

健康检查同时执行 SQL SELECT 1 和 Redis PING；Compose 用依赖健康状态编排。演示与自动化测试使用不同项目名、网络与数据卷。初始迁移是自建版本表与可重复执行 DDL，适用于单实例启动；没有实现 Flyway 的校验和、多实例迁移锁和自动回滚。

## 后续可扩展方向

优先学习退款与退押的账务模型、密码修改/重置、迁移到受支持的框架基线，再考虑压测后的索引优化、事务后事件、前端按需加载。不要为了简历引入没有业务理由的消息队列或微服务。
