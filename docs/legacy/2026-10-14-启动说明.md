# rentalSys 本地启动

先打开 Docker Desktop，然后在本目录的 PowerShell 中运行：

```powershell
# 源码更新后自动重新编译，再启动前端、后端、MySQL 和 Redis。
.\启动demo.ps1
```

页面：http://localhost/login

示例管理员：`admin`，密码：`111111`。用户管理页面：http://localhost/user

```powershell
# 停止本项目服务，保留数据库和 Redis 数据卷。
.\停止demo.ps1
```

2026-10-14 更新：这次使用 JDK 11 从 47 个 Java 源文件重新编译，运行配置取自当前 `system-admin/src/main/resources`，没有复用旧 class 文件。依赖 JAR 复用项目原有 `out/artifacts/admin/WEB-INF/lib`，运行副本放在 `.local-run/admin`。这是源码编译与展开目录部署，未执行 Maven WAR 打包。

镜像来源为 [Docker Hub 官方 Tomcat 镜像](https://hub.docker.com/_/tomcat)：编译使用 `tomcat:9.0.123-jdk11-temurin-noble`，运行使用 `tomcat:9.0.123-jre11-temurin-noble`。MySQL 和 Redis 复用已有镜像。启动脚本使用 `--pull never`，不会自动下载新增镜像。

源码和依赖的指纹保存在 `.local-run/source-fingerprint.txt`。更新 Java、资源文件或依赖 JAR 后，启动脚本会重新编译，并备份旧运行副本。前端继续使用 Vue 开发服务器，修改前端源码后自动重新编译。

已有 `rentalsys-demo_mysql_data` 和 `rentalsys-demo_redis_data` 数据卷继续保留。SQL 原始导入仅作用于空卷；`.local-run/repair-demo-auth.sql` 只补齐原始示例管理员的角色和查询权限，重复执行不会清空表。

本轮修改前的源码原件在 `.local-run/original-sources`，数据库备份在 `.local-run/rental-before-startup-fixes.sql`。检查过程与未完成部分见 `项目检查记录.md`。

```powershell
# 查看容器状态与最近的后端日志。
docker compose -f .local-run/compose.yaml ps
docker compose -f .local-run/compose.yaml logs --tail 50 backend
```
