## 本轮修复

1. 原始示例管理员 ID 为 10000，但 `user_role` 关联为 1，管理员角色标签也为空。修正初始化 SQL，并对既有数据库幂等补齐正确关联、`admin` 标签及 `system:user:query` 查询权限。没有重新导入或清空业务表。
2. `getInfo` 的 `WHERE r.del_flag=0` 会过滤掉没有角色的用户，原服务接着访问空对象，实际返回 500。把角色删除标记过滤移入 JOIN，并按空集合处理没有关联角色的情况。
3. `PermissionAspect` 缺少 Redis 工具的依赖注入，用户详情实际返回 500。补充 `@Resource`；缺少角色或权限缓存时按无权限处理，返回 403。
4. Redis 缓存未命中时原代码把 null 传给 Jackson；补充正常的空值返回。
5. 登录写入的新键为 `token:用户名:令牌`，续期和退出却仍使用 `token:令牌`。改为续期实际会话键，退出时删除正确会话及角色、权限缓存。
6. 重新建立启动、停止和编译脚本。使用当前源码和资源配置生成运行副本，旧 class 文件不进入本轮编译结果。

修改前源码：`.local-run/original-sources`。数据库备份：`.local-run/rental-before-startup-fixes.sql`。

## 待处理问题

- **其余 5 个分页接口实际返回 500。** 控制器直接接收 `PageRequest`，Spring MVC 无法构造它。Tomcat 日志明确报错 `No primary or default constructor found for class org.springframework.data.domain.PageRequest`。对应 role、menu、operLog、userRole、roleMenu 模块；没有为这些尚未接入前端的模块改造分页接口。
- **用户列表响应含 password 字段，密码存储为明文。** 本轮接口检查确认响应含该字段。后续应单独设计密码存储及输出 DTO，避免把密码放进列表或详情响应。
- **用户角色、角色菜单写 SQL 尚未完成。** 两个 Mapper 的 INSERT 列表及 UPDATE SET 为空，不能作为已实现的管理能力；它们的表使用复合主键，当前删除接口只接收一列 ID。要删除单条关联还是整组关联，需求未明确，待确认。
- **角色与客户前端页面尚未实现。** 角色菜单调用 `open('role')`，路由中只有 login、main、user；客户管理没有绑定页面动作。
- **查询语义和分页一致性待确认。** 用户列表使用 `LIKE #{值}`，数量统计使用等号；含 `%` 的输入可能使列表与总数不一致。是否支持模糊匹配，需求未明确，待确认。查询按钮也没有把页码归零。
- **失败和过期会话处理待完善。** 前端 LOGIN / GET_INFO 的 Promise 缺少失败分支，路由恢复没有等待权限获取；后端登录还同步依赖外部 IP 地址查询，RestTemplate 未设置超时。
- **权限覆盖和事务配置需另行核实。** 当前只在用户详情接口看到权限注解；其他写接口主要依赖登录拦截。XML 声明了 tx:advice，但没有看到把它连接到服务方法的 advisor。哪些操作需要哪些权限以及关联写入的事务边界，需求未明确，待确认。
- **Maven 打包未验证。** 本轮使用 JDK 11、现有依赖 JAR 和当前源码完成编译及部署。POM 的编译插件引用 `${java.version}`，而当前 properties 未定义这个属性；正式整理 Maven 构建时需要核对。

当前已验证的使用入口为登录与用户列表。上述待处理问题不能视为已经实现或通过回归。
