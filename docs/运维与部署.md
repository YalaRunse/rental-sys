# 运维与部署

## 运行要求与来源

Windows + PowerShell 7 + Docker Desktop（Linux 容器），本机已使用 PowerShell 7.6.5 验证，镜像为 linux/amd64。首次准备约需数 GB 空间；具体以 Docker 的镜像和卷实际占用为准。Windows 不需要全局安装 Java / Maven / Node。未验证旧版 Windows PowerShell 5.1 对 UTF-8 脚本的兼容性。

| 来源 | 镜像 / 软件 | 保存位置 |
| --- | --- | --- |
| Docker Hub 官方 library/maven | maven:3.10.0-eclipse-temurin-11-noble | Docker 镜像库 |
| Docker Hub 官方 library/tomcat | tomcat:9.0.123-jre11-temurin-noble | Docker 镜像库 |

当前电脑已获得下载许可并准备镜像；在其他电脑可先检查 docker image ls，再按需拉取：

~~~powershell
docker pull --platform linux/amd64 maven:3.10.0-eclipse-temurin-11-noble
docker pull --platform linux/amd64 tomcat:9.0.123-jre11-temurin-noble
docker pull --platform linux/amd64 mysql:8.4.11
docker pull --platform linux/amd64 redis:7.4.11-alpine

~~~

[官方 Maven 镜像定义](https://github.com/docker-library/official-images/blob/master/library/maven)、[官方 Tomcat 镜像](https://hub.docker.com/_/tomcat)。标签将来可能更新，同名标签不是字节级不变；本次实际镜像摘要保存在 evidence/build-manifest.json。

## 编译与启动

~~~powershell
.\启动demo.ps1
.\初始化演示数据.ps1
~~~

编译项目.ps1：容器中 Maven clean package → 单元测试 → admin.war；源码指纹不变时复用。替换 WAR 前会停止本项目演示和测试后端，避免 Tomcat 读到半成品。因此测试触发重编译后，需重新启动演示服务。

前端 helper：只读挂载源码 → 临时 Node 容器 npm ci → build → 成功后替换 ydl-ui/dist；不会使用或清空原 Windows node_modules。启动脚本随后构建生产静态服务镜像并等待四个服务健康。前端更新后需重新运行启动脚本，不再使用开发热更新。

首次后端启动自动增量建表并记录版本；已有 user / role / user_role 及旧记录保留，明文口令转 PBKDF2 散列。默认管理员 admin / 111111 仅供本机；旧管理员已改过口令时继续使用原口令，不能依赖默认值。

示例导入通过业务 API 执行，管理员登录会替换之前会话。存在 DEMO- 房源时整个导入跳过，保留手工编辑；若第一次导入中断，应先检查已经创建的数据，脚本不提供跨所有 API 的整体事务或自动补齐。

## 配置与端口

默认页面 http://localhost/login；后端直连 http://127.0.0.1:8088/admin/api/health。数据库和 Redis 不发布主机端口。Compose 项目 rentalsys-demo；所有对主机发布的端口仅绑定 127.0.0.1。

~~~powershell
Copy-Item .env.example .env
# 用编辑器修改 WEB_PORT / BACKEND_PORT 等值，然后重新启动。
~~~

启动与停止脚本显式读取项目根 .env。初始化示例脚本在 Docker 内网访问后端，不受主机端口修改影响。环境变量优先级高于 .env。已有 MySQL 数据卷的口令不会因为改 .env 自动更新，必须保持与已初始化账户一致。

.env 不进入 Git。向外部署前需自行设计独立口令、HTTPS、网络访问控制、账号密码修改、框架升级及备份恢复流程；当前启动方案定位本机演示。

## 常用检查与停止

~~~powershell
docker compose -p rentalsys-demo -f deploy/compose.yaml --profile web ps
docker compose -p rentalsys-demo -f deploy/compose.yaml logs --tail 80 backend
docker compose -p rentalsys-demo -f deploy/compose.yaml logs --tail 40 frontend
Invoke-RestMethod http://127.0.0.1:8088/admin/api/health
.\停止demo.ps1
~~~

使用自定义 .env 时，手工 Compose 命令也可增加 --env-file .env。业务日志写 backend_logs 卷中的 /logs，并带 requestId；日志采用滚动策略。排查时对照接口响应头 X-Request-Id、错误体与操作审计。

停止脚本只停止本项目，保留数据。不要对包含业务数据的项目执行 down -v。不要用 Docker Desktop 恢复出厂设置修复本项目。

## 数据备份

~~~powershell
.\备份数据.ps1
~~~

脚本先在 MySQL 容器内 mysqldump --single-transaction，再 docker cp，避免 PowerShell 文本重定向改写编码。输出为 .local-run/backups/rental-日期时间.sql；SQL 包含用户散列与业务资料，请只保存在本机，勿提交仓库。脚本校验导出成功和文件非空，不等于完成灾备恢复演练。

本轮改造前源码 ZIP 和数据库 SQL 也保存在 .local-run/backups。恢复应先停止写入、另做当前备份，并将目标备份导入全新的隔离 MySQL 实例验证，确认后再由操作者决定是否替换展示数据。本版没有自动覆盖原库的恢复脚本。

## 自动化测试

~~~powershell
.\验证项目.ps1
# 排查测试环境时可暂时保留容器：
.\验证项目.ps1 -KeepEnvironment
~~~

测试项目 rentalsys-qa，网络和数据库/Redis 卷均独立；端口 18089，不连接演示数据库。测试结束默认停止容器，保留测试卷便于排查。每轮业务数据使用随机 IT 前缀，不要求清空库。测试账号与历史记录可留存于隔离测试库。

## Docker Desktop 通信文件故障

曾出现 initializing Ingest server / sailor-ingest.sock / cannot be accessed by the system，故障发生在 Docker 引擎启动阶段。当前已恢复，MySQL、Redis、Tomcat 与前端均能健康启动。

当时仅在退出 Docker 相关进程后，核对 LocalAppData 下 Docker/run 和 docker-secrets-engine 的实际内容均为残留通信链接，再将目录改名备份、重建空目录并启动 Docker。此步骤不触碰 Docker 数据盘，也没有恢复出厂设置。

不要将这段历史处理做成无条件删除脚本：先确认 Docker 已退出、目录路径和内容确实符合上述情况；有普通数据文件或路径不同就停止处理。错误截图本身不足以判断可以删目录。
